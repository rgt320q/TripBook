# AGENTS.md

TripBook: Flutter travel-planning app (map pins, groups, routes, community routes) with a Firebase backend (Auth, Firestore, Storage, Functions, Messaging, Crashlytics). Targets web + Android/iOS. Dev env is Windows (pwsh).

## Commands
- `flutter pub get` — install Dart deps
- `flutter analyze` — clean of errors; ~105 pre-existing info lints (`withOpacity`, `use_build_context_synchronously`, etc.) are accepted noise, don't mass-fix
- `flutter test` — runs tests in `test/`; currently 3 pre-existing failures (stale counter `widget_test.dart`, 2 `firestore_service_test` cases missing a `.get()` stub), so "red" does not imply your change broke something
- `dart run build_runner build --delete-conflicting-outputs` — regenerate mockito `*.mocks.dart` after editing `@GenerateMocks` in a test
- Localization is auto-generated during build (`generate: true` + `l10n.yaml`); run `flutter gen-l10n` if you want it before build
- Functions (Node 22, firebase-functions v2): `cd functions && npm install`, deploy via `firebase deploy --only functions`

## Setup — everything below is gitignored, a fresh clone will NOT build/run without it
- `assets/.env` — copy from `.env.template`; loaded at runtime via `dotenv.load(fileName: "assets/.env")` in `lib/main.dart:30` (only `assets/.env` is read, the root `.env` copy in the template is not used)
- `lib/firebase_options.dart` — generated by `flutterfire configure`; imported by `main.dart`
- `firebase.json`, `android/app/google-services.json` — kept local per-project
- `android/secrets.properties` — holds `GOOGLE_MAPS_API_KEY`; injected as a string resource via `resValue` in `android/app/build.gradle.kts:40`

## Architecture
- `lib/services/directions_service.dart` is the Maps integration hub. All Maps **data** calls (directions, geocode, autocomplete, place details) go through the Firebase Functions proxy on **every platform** (`https://us-central1-tripbook-68238.cloudfunctions.net/getDirections|getAutocomplete|getPlaceDetails|getGeocode`) with a Firebase ID token as `Bearer`, so the Maps data API key never ships in the app. The proxy requires the functions deployed with the `MAPS_PROXY_KEY` secret set in Secret Manager (`functions/index.js`).
- Keys are split by purpose:
  - **Web map rendering** (Maps JS): `GOOGLE_MAPS_API_KEY` in `assets/.env` (referrer-restricted browser key).
  - **Android native map tiles**: `GOOGLE_MAPS_API_KEY` in `android/secrets.properties`, injected via `resValue` in `android/app/build.gradle.kts:40` (package+SHA-1 restricted key).
  - **Server-side data calls**: `MAPS_PROXY_KEY` secret (never in any client).
- `functions/` only proxies Google Maps endpoints; all app data logic lives in the Flutter app.
- Dual persistence: `lib/services/firestore_service.dart` (Cloud Firestore under `users/{uid}/...`) and `lib/services/database_service.dart` (sqflite `travel_log.db`; on web the DB is null and falls back to in-memory).
- Google Maps JS is loaded on web only via the conditional import `lib/web_script_loader.dart` / `lib/non_web_script_loader.dart`.
- Localization: `lib/l10n/app_en.arb` + `app_tr.arb`. New user-visible strings go in **both** .arb files; `AppLocalizations` is used throughout.

## Gotchas
- `test/` is entirely gitignored (unusual) — tests and `.mocks.dart` files are local-only, not committed.
- Firebase project: `tripbook-68238`, region `us-central1`, Firestore `eur3`.
- `doc/ToDo.txt` tracks open bugs (includes a reminder to rotate API keys before going live).
- README.md is a user guide (EN+TR) and lags the code — community routes, ratings, comments, avatars, and FCM are in the code but absent from the README. Don't treat it as an API/schema reference.
